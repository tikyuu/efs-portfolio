# API_SQS — 非同期の帳票作成

API Gateway・SQS・Lambdaを使い、指定した月の売上表PDFを作る学習用プロジェクト。
依頼の受付と帳票生成を分ける理由、キューによる処理待ち、Lambdaの実行と結果の保存を理解する。

## 決めた要件

| 項目 | 内容 |
| --- | --- |
| 作成依頼 | 年・月を指定する（例：2026年10月） |
| APIの種類 | REST API。受付時の入力検証とWAFとの直接連携を学ぶために選択（両機能は未実装、WAFの追加は要件・費用確認後に判断） |
| 元データ | S3に置く、架空の売上データのCSV |
| PDFの内容 | 対象年月、売上日、商品名、数量、金額、合計金額 |
| 出力先 | S3 |
| 結果の確認 | S3管理画面から完成したPDFをダウンロードする |

## 処理の流れ

1. API Gatewayが年・月を含む帳票作成依頼を受け付け、SQSへ送る。
2. APIは依頼の受付結果を返す。この時点ではPDFの完成を保証しない。
3. LambdaのイベントソースマッピングがSQSの依頼を取得し、Lambda関数を呼び出す。
4. LambdaがS3から元のCSVを読み、指定された月の売上を取り出す。
5. PythonのPDF生成ライブラリで売上表を作り、S3へ保存する。
6. 利用者がS3管理画面からPDFをダウンロードする。

SQSに入れるのは作成依頼であり、売上CSVや完成したPDFそのものではない。
SVFは使用せず、PDFのレイアウトもPython側で指定する。

## 現在地と次の工程

既存の[draw.io構成図](../docs/architecture/efs-architecture.drawio)のシート1下段に、独立した帳票作成の流れを追加した。
`infra/` にTerraform・AWS Providerのバージョン指定、東京リージョンの指定、通常のSQSキューとDLQを定義済み。
REST API本体、`/reports` のパス、IAM認証を必須とする `POST` メソッドを `api_gateway.tf` に定義済み。SQS統合の接続先と使用するIAMロールまで指定済みだが、送信内容の変換・応答設定・デプロイは未定義で、呼び出せる状態にはなっていない。呼び出し元の認証方法と既存権限は未確認で、呼び出し元のユーザー・ロールの作成や権限変更は行っていない。
`iam.tf` にAPI Gateway用ロールと信頼ポリシー、通常キューへの `sqs:SendMessage` だけを許可するインラインポリシーを定義済み。`providers.tf` のデータソースで適用先アカウントIDを参照し、SQS統合の接続先に使用する。
アプリとLambda・S3の定義は未作成。AWSへの適用と動作検証は未実施。
EFS・Tomcatの既存成果は保持し、このフォルダで次の学習を進める。

| SQSの設定 | 通常のキュー | DLQ |
| --- | --- | --- |
| 名前 | `sqs-reports` | `sqs-reports-dlq` |
| 種類 | スタンダード | スタンダード |
| メッセージ保持期間 | 4日 | 14日 |
| 暗号化 | SSE-SQS | SSE-SQS |

成功した依頼は削除される。保持期間は未削除の依頼に適用され、スタンダードキューではDLQへ移る前の経過時間も含む。
可視性タイムアウト180秒は、今後定義するLambdaの実行タイムアウトを30秒とする想定に合わせた値。実際の処理時間は未測定。
